# K-POP 앨범 판매처별 특전 비교

같은 앨범이라도 **어디서 사느냐에 따라 받는 포토카드가 다르다.**
그런데 그걸 한곳에 모아둔 데가 없어서, 팬들이 컴백마다 트위터·더쿠에 손으로 정리해 올린다.

이 도구는 그걸 자동으로 한다 — **예판 중인 컴백을 찾아내고, 판매처 4곳을 긁어, 앨범별 비교 페이지를 만든다.**

```bash
node build.mjs                 # 전체 (예판 중인 앨범 전부)
node build.mjs TAEMIN          # 아티스트·앨범명으로 필터
node build.mjs --max=5         # 개수 제한

SITE_URL=https://도메인 node build.mjs   # 배포용 (canonical·og:url·sitemap 포함)
```

Node 18+ (내장 fetch). 판매처 4곳은 의존성 0개로 돌고, **위드뮤만 헤드리스(playwright)** 가 필요하다.
출력은 `out/index.html` + `out/album/{slug}.html` + `out/sitemap.xml` + `out/robots.txt`.

### SITE_URL

이 서비스의 유입은 ①검색(아티스트명이 앞에 붙는 롱테일)과 ②팬이 X·카톡에 링크를 퍼가는 것, 둘이다.
①은 `sitemap.xml`이, ②는 OG 카드가 결정한다. 둘 다 **절대주소**를 요구하므로 `SITE_URL`이 필요하다.

**안 넣으면** canonical·og:url·sitemap을 아예 생략한다. 틀린 도메인을 박는 것보다 없는 게 낫기 때문이다.
(빌드 로그에 경고가 뜬다.)

- 로컬 확인: 그냥 `node build.mjs` — 절대주소 없이도 페이지는 정상
- 배포: GitHub 저장소 → Settings → Variables에 `SITE_URL` 추가. 워크플로가 읽어간다

## 어떻게 도는가

```
① 컴백 탐지    위버스샵 158팀을 훑어 예판 중인 앨범을 찾는다 (~4초)
② 수집        앨범마다 판매처 4곳 검색 + 상세
③ 정규화      상품명을 (이벤트·에디션·포장) 3축으로 분해해 판매처 간 매칭
④ 계산        배송비·쿠폰 포함 총액, 조합 최적화
⑤ 렌더        앨범별 정적 HTML + 인덱스
```

### ① 컴백 탐지가 핵심이다

수동으로 앨범을 넣을 필요가 없다. 필터 두 개면 된다.

- `icons`에 **`PRE_ORDER`** → 예약판매 중
- **`albumChartTargets`**(한터·써클 반영) → 실제 음반. 이 한 줄로 MD·포토북·응원봉이 전부 걸러진다

여기에 `[SHOWCASE LIVE]` `[YOUTUBE GIFT]` 같은 이벤트 표식을 앨범명으로 오인하던 걸 고쳐서 **88개 → 17개**로 정확해졌다.

### ③ 정규화가 매칭의 전부다

판매처마다 같은 상품을 다르게 적는다.

```
[COMEBACK LIVE] [PHASE I : Soft Violence] (PHOTO BOOK Ver.) (Set)      위버스샵
[케타포 Special Gift] [2CD 세트상품] 태민 - […] (PHOTO BOOK Ver.)        Ktown4u
[SET] 태민 - PHASE I : Soft Violence (PHOTO BOOK Ver.)[2종 세트]         알라딘
태민 (TAEMIN) - [PHASE I : Soft Violence] (PHOTO BOOK Ver.) (2종 세트)   사운드웨이브
```

세 축으로 분해한다.

| 축 | 예 | 매칭 키 |
|---|---|:-:|
| **이벤트** | COMEBACK LIVE · 케타포 Special Gift · 럭키드로우 | ✗ 표시용 |
| **에디션** | PHOTO BOOK Ver. · JEWEL Ver. · NEMO Ver. | ✓ |
| **포장** | 단품 / 랜덤 / 세트 | ✓ |

**세트 "개수"는 키에서 뺐다.** 위버스샵은 `(Set)`이라고만 쓰고 개수를 안 적기 때문이다.

## 판매처

| 판매처 | 접근 | 특전 | 배송비 |
|---|:-:|---|---|
| **위버스샵** | `__NEXT_DATA__` SSR | **구조화 텍스트 + 특전 안내 이미지** | 미확인 (로그인 벽) |
| **알라딘** | 정적 HTML | 상세에 내용·기간 | **무료** (음반) |
| **Ktown4u** | 정적 HTML (`kr.` 서브도메인 = 원화) | 상품 JSON의 옵션명 | **3,000원 / 3만↑ 무료** |
| **사운드웨이브** | 정적 HTML (카페24) | 상세 설명 | **3,000원 / 5만↑ 무료** |
| **위드뮤** | **헤드리스(playwright)** | 상세에 특전 문구 없음 | 미확인 |
| **메이크스타** | **커머스 API** (정적 fetch) | 상품은 안 긁고 **팬사인회·이벤트만** | — |

### 팬사인회는 메이크스타에만 있다

다른 판매처는 팬싸 정보를 아예 안 준다 — 위버스샵 `eventGuides` 37건을 조사해도 `BENEFIT` 타입뿐이고,
알라딘·사운드웨이브는 "팬사인회" 검색이 0건이다.

처음엔 검색 페이지를 헤드리스로 열어 본문 텍스트를 긁었다. **그건 틀린 접근이었다** —
검색이 아티스트명 표기에 민감해서 16개 중 5개 앨범에만 붙었고, 무엇보다
"이벤트가 없다"와 "검색이 못 찾았다"를 구분할 수 없었다.

사이트가 Nuxt이고 그 커머스 API가 열려 있다. 진행 중 이벤트를 **전량** 준다.

```
GET new-commerce-api.makestar.com/v2/commerce/product_event/events/
    ?eventFilterStatus=ON_SALE&size=200
```

빌드당 한 번 받아 두고 로컬에서 고른다. **검색어 민감도가 사라지고, 브라우저가 필요 없고,
없으면 정말로 없는 것이 된다.** (HTML 페이지는 여전히 429로 막힌다 — 링크로만 쓴다.)

| 타입 | 뜻 |
|---|---|
| `MEET&CALL` `VIDEOCALL` | **영상통화 팬사인회** |
| `PHOTOCARD` | 예약 특전 포토카드 |
| `LUCKYDRAW` | 럭키드로우 |
| `ETC` | 대면 사인회 등 |

**어느 앨범에 붙일지는 신호 셋 중 둘 이상**으로 정한다. 하나만으론 붙이지 않는다.

| 신호 | 왜 단독으론 못 믿나 |
|---|---|
| 아티스트 | 소속사가 멤버 솔로를 그룹 계정으로 판다 (위버스샵 i-dle 계정 = 소연 솔로 앨범) |
| 앨범명 | 위버스샵은 영어(`What a Wonderful Life`), 국내는 한국어(`끝내주는 인생`) |
| 발매일 | ±10일. 제목이 영영 안 맞는 앨범을 건지는 마지막 끈 |

낱말 경계를 지켜 대조한다. 공백까지 지우고 비교했더니 `TUNE`이 `TUNEXX` 안에서 발견돼
TUIDE의 [TUNE & PLAY]가 튜넥스 이벤트에 붙었다.

상세(`/v2/commerce/product_event/{id}/`)에서 **어떤 버전을 얼마에 사야 응모되는지**까지 가져온다.
이 이벤트들은 메이크스타에서 사야 응모되는 것이라, 아래 특전표의 가격과 나란히 놓고 봐야 한다.

**한계** — 16개 앨범 중 8개에 붙는다. 나머지 8개는 진행 중인 이벤트가 실제로 없다.
반대로 메이크스타 19건 중 11건은 위버스샵 예판에 안 잡힌 앨범이라 붙일 곳이 없다
(도경수·앤팀·베이비몬스터 등). **이벤트 목록이 컴백 탐지보다 넓다.**

**위드뮤가 가격이 다르다.** 다른 4사는 정가로 같은데 위드뮤만 비싸다 —
NEMO 16,000원 vs 13,800원, PHOTO BOOK 24,000원 vs 20,500원. "국내는 가격이 같다"는 더 이상 참이 아니다.

**아직 막힌 곳** — YES24(검색결과가 1건만 렌더) · 뮤직플랜트 · 뮤직코리아 · 핫트랙스.

### 헤드리스는 최소한으로 쓴다

`src/browser.mjs`가 공용 브라우저를 하나 띄우고 이미지·폰트·미디어 요청은 막는다.
위드뮤는 **앨범당 검색 1회**만 하고 상세는 안 연다 — 상세에 특전 문구가 없어서(실측 0건) 비용만 든다.
playwright가 없으면 위드뮤만 조용히 빠지고 나머지 4사는 그대로 돈다.

## 알아둘 것

**특전 상태를 넷으로 구분한다.** `—` 하나로 뭉뚱그리지 않는다.

| 상태 | 뜻 |
|---|---|
| 내용 표시 | 파싱 성공 |
| `특전 없음` | 위버스샵 `icons`에 BENEFIT 없음 = 단정 가능 |
| `특전 있음 · 구성 비공개` | Ktown4u가 *"특전 (구성은 비공개입니다)"*로 명시 |
| `증정 종료` / `확인 못함` | 알라딘 종료 문구 / 요청 실패 |

**쿠폰은 총액에서 빼지 않는다.** 알라딘 상품 페이지의 "최대 7,000원 할인쿠폰"은
**"받기"를 눌러야 하고**, `8월 음반 전종 쿠폰 이벤트`라는 **기간 한정 행사**다 (2026-08-27 확인).
그래서 별도 항목으로만 표시한다.

**국내 판매처 상품가는 대체로 같다.** 정가 판매라서다.
차이가 나는 건 ⓐ3만원 미만 소액 구매의 배송비 ⓑ쿠폰 ⓒ**특전 구성**뿐이고, 이 중 ⓒ가 이 도구의 존재 이유다.

## 배포

정적 파일이라 `out/`을 그대로 서빙하면 된다.

- **Vercel** — `vercel.json`에 `outputDirectory: "out"`, 빌드 없음
- **갱신** — `.github/workflows/rebuild.yml`이 하루 두 번(KST 10시·19시) 다시 긁어 `out/`을 커밋한다.
  Vercel이 그 커밋을 보고 자동 재배포한다

빌드를 Vercel에서 돌리지 않는 이유는 **판매처들이 클라우드 IP를 막을 수 있어서**다.
GitHub Actions에서 긁고 결과만 커밋하는 편이 안전하다.
