# K-POP 앨범 판매처별 특전 비교

같은 앨범이라도 **어디서 사느냐에 따라 받는 포토카드가 다르다.**
그런데 그걸 한곳에 모아둔 데가 없어서, 팬들이 컴백마다 트위터·더쿠에 손으로 정리해 올린다.

이 도구는 그걸 자동으로 한다 — **예판 중인 컴백을 찾아내고, 판매처 4곳을 긁어, 앨범별 비교 페이지를 만든다.**

```bash
node build.mjs                 # 전체 (예판 중인 앨범 전부)
node build.mjs TAEMIN          # 아티스트·앨범명으로 필터
node build.mjs --max=5         # 개수 제한
                               # ↑ 둘 다 부분 빌드다. 인덱스·sitemap·alarm.ics는
                               #   지난 결과에 머지된다 (덮어쓰지 않는다)

SITE_URL=https://도메인 node build.mjs   # 배포용 (canonical·og:url·sitemap 포함)
```

Node 18+ (내장 fetch). 판매처 6곳은 의존성 0개로 돌고, **위드뮤만 헤드리스(playwright)** 가 필요하다.
출력은 `out/index.html` + `out/album/{slug}.html` + `out/alarm.ics` + `out/sitemap.xml` + `out/robots.txt`.

### SITE_URL

이 서비스의 유입은 ①검색(아티스트명이 앞에 붙는 롱테일)과 ②팬이 X·카톡에 링크를 퍼가는 것, 둘이다.
①은 `sitemap.xml`이, ②는 OG 카드가 결정한다. 둘 다 **절대주소**를 요구하므로 `SITE_URL`이 필요하다.

**안 넣으면** canonical·og:url·sitemap을 아예 생략한다. 틀린 도메인을 박는 것보다 없는 게 낫기 때문이다.
(빌드 로그에 경고가 뜬다.)

- 로컬 확인: 그냥 `node build.mjs` — 절대주소 없이도 페이지는 정상
- 배포: GitHub 저장소 → Settings → Variables에 `SITE_URL` 추가. 워크플로가 읽어간다

## 어떻게 도는가

```
① 컴백 탐지    위버스샵 158팀을 훑어 예판 중인 앨범을 찾는다 (~4초)
② 수집        앨범마다 판매처 4곳 검색 + 상세
③ 정규화      상품명을 (이벤트·에디션·포장) 3축으로 분해해 판매처 간 매칭
④ 계산        배송비·쿠폰 포함 총액, 조합 최적화
⑤ 렌더        앨범별 정적 HTML + 인덱스
```

### ① 컴백 탐지가 핵심이다

수동으로 앨범을 넣을 필요가 없다. 필터 두 개면 된다.

- `icons`에 **`PRE_ORDER`** → 예약판매 중
- **`albumChartTargets`**(한터·써클 반영) → 실제 음반. 이 한 줄로 MD·포토북·응원봉이 전부 걸러진다

여기에 `[SHOWCASE LIVE]` `[YOUTUBE GIFT]` 같은 이벤트 표식을 앨범명으로 오인하던 걸 고쳐서 **88개 → 17개**로 정확해졌다.

### ③ 정규화가 매칭의 전부다

판매처마다 같은 상품을 다르게 적는다.

```
[COMEBACK LIVE] [PHASE I : Soft Violence] (PHOTO BOOK Ver.) (Set)      위버스샵
[케타포 Special Gift] [2CD 세트상품] 태민 - […] (PHOTO BOOK Ver.)        Ktown4u
[SET] 태민 - PHASE I : Soft Violence (PHOTO BOOK Ver.)[2종 세트]         알라딘
태민 (TAEMIN) - [PHASE I : Soft Violence] (PHOTO BOOK Ver.) (2종 세트)   사운드웨이브
```

세 축으로 분해한다.

| 축 | 예 | 매칭 키 |
|---|---|:-:|
| **이벤트** | COMEBACK LIVE · 케타포 Special Gift · 럭키드로우 | ✗ 표시용 |
| **에디션** | PHOTO BOOK Ver. · JEWEL Ver. · NEMO Ver. | ✓ |
| **포장** | 단품 / 랜덤 / 세트 | ✓ |

**세트 "개수"는 키에서 뺐다.** 위버스샵은 `(Set)`이라고만 쓰고 개수를 안 적기 때문이다.

## 판매처

| 판매처 | 접근 | 특전 | 배송비 |
|---|:-:|---|---|
| **위버스샵** | `__NEXT_DATA__` SSR | **구조화 텍스트 + 특전 안내 이미지** | 미확인 (로그인 벽) |
| **알라딘** | 정적 HTML | 상세에 내용·기간 | **무료** (음반) |
| **Ktown4u** | 정적 HTML (`kr.` 서브도메인 = 원화) | 상품 JSON의 옵션명 | **3,000원 / 3만↑ 무료** |
| **사운드웨이브** | 정적 HTML (카페24) | 상세 설명 | **3,000원 / 5만↑ 무료** |
| **위드뮤** | **헤드리스(playwright)** | 상세에 특전 문구 없음 | 미확인 |
| **뮤직플랜트** | 정적 HTML (위사몰) | 상세 설명 | **3,000원 / 5만↑ 무료** |
| **애플뮤직** | 정적 HTML (메이크샵) | 상세 설명 + **구성품** | **3,000원 / 5만↑ 무료** |
| **메이크스타** | **커머스 API** (정적 fetch) | 상품은 안 긁고 **팬사인회·이벤트만** | — |

### 팬사인회는 메이크스타에만 있다

다른 판매처는 팬싸 정보를 아예 안 준다 — 위버스샵 `eventGuides` 37건을 조사해도 `BENEFIT` 타입뿐이고,
알라딘·사운드웨이브는 "팬사인회" 검색이 0건이다.

처음엔 검색 페이지를 헤드리스로 열어 본문 텍스트를 긁었다. **그건 틀린 접근이었다** —
검색이 아티스트명 표기에 민감해서 16개 중 5개 앨범에만 붙었고, 무엇보다
"이벤트가 없다"와 "검색이 못 찾았다"를 구분할 수 없었다.

사이트가 Nuxt이고 그 커머스 API가 열려 있다. 진행 중 이벤트를 **전량** 준다.

```
GET new-commerce-api.makestar.com/v2/commerce/product_event/events/
    ?eventFilterStatus=ON_SALE&size=200
```

빌드당 한 번 받아 두고 로컬에서 고른다. **검색어 민감도가 사라지고, 브라우저가 필요 없고,
없으면 정말로 없는 것이 된다.** (HTML 페이지는 여전히 429로 막힌다 — 링크로만 쓴다.)

| 타입 | 뜻 |
|---|---|
| `MEET&CALL` `VIDEOCALL` | **영상통화 팬사인회** |
| `PHOTOCARD` | 예약 특전 포토카드 |
| `LUCKYDRAW` | 럭키드로우 |
| `ETC` | 대면 사인회 등 |

**어느 앨범에 붙일지는 신호 셋 중 둘 이상**으로 정한다. 하나만으론 붙이지 않는다.

| 신호 | 왜 단독으론 못 믿나 |
|---|---|
| 아티스트 | 소속사가 멤버 솔로를 그룹 계정으로 판다 (위버스샵 i-dle 계정 = 소연 솔로 앨범) |
| 앨범명 | 위버스샵은 영어(`What a Wonderful Life`), 국내는 한국어(`끝내주는 인생`) |
| 발매일 | ±10일. 제목이 영영 안 맞는 앨범을 건지는 마지막 끈 |

낱말 경계를 지켜 대조한다. 공백까지 지우고 비교했더니 `TUNE`이 `TUNEXX` 안에서 발견돼
TUIDE의 [TUNE & PLAY]가 튜넥스 이벤트에 붙었다.

상세(`/v2/commerce/product_event/{id}/`)에서 **어떤 버전을 얼마에 사야 응모되는지**까지 가져온다.
이 이벤트들은 메이크스타에서 사야 응모되는 것이라, 아래 특전표의 가격과 나란히 놓고 봐야 한다.

**한계** — 16개 앨범 중 8개에 붙는다. 나머지 8개는 진행 중인 이벤트가 실제로 없다.
반대로 메이크스타 19건 중 11건은 위버스샵 예판에 안 잡힌 앨범이라 붙일 곳이 없다
(도경수·앤팀·베이비몬스터 등). **이벤트 목록이 컴백 탐지보다 넓다.**

### 마감 카운트다운과 캘린더 알람

**"오픈까지 남은 시간"은 만들 수 없다.** 실측 결과 아무도 미리 공개하지 않는다.

| 출처 | 상태값 | 뜻 |
|---|---|---|
| 메이크스타 | `ON_SALE` / `ENDED` 둘뿐 | 열려야 목록에 뜬다. 오픈 예정은 없다 |
| 위버스샵 | `SALE` / `SOLD_OUT` 둘뿐 | 판매 중인 것만 준다 |

예판 오픈 시각은 소속사 SNS에만 있고 그건 기계로 읽을 대상이 아니다.
대신 **이미 열린 것의 마감은 초 단위로 정확하고**, 팬을 실제로 급하게 만드는 쪽도 마감이다.

| 무엇 | 출처 | 정밀도 |
|---|---|---|
| 이벤트 응모 마감 | 메이크스타 `salesEndAt` | 초 (`2026-08-30T00:59:59+09:00`) |
| 예약 배송 시작 | 위버스샵 `deliveryStartAt` | 초 (보통 19:00 KST) |

카운트다운은 **브라우저에서 돈다.** 페이지엔 절대 시각만 박고 남은 시간은 클라이언트가 센다 —
하루 두 번만 다시 만들어도 언제 열든 맞는다.

**알람은 웹푸시가 아니라 캘린더(.ics)다.** 푸시를 하려면 구독 정보를 담을 DB와 발송 서버가 필요한데,
캘린더는 그게 없어도 결과가 더 낫다.

- 브라우저를 닫아도 알림이 온다 (웹푸시는 iOS에서 홈 화면 설치가 전제다)
- **구독(`webcal://도메인/alarm.ics`)하면 리빌드마다 캘린더가 알아서 갱신된다.** 새 컴백의 마감도 따라 들어온다
- 계정도 이메일 수집도 없다

일정마다 **하루 전·1시간 전** 알람을 넣는다. UID를 `{slug}-{이벤트id}`로 고정해서,
목록 순서가 바뀌어도 구독자 캘린더에 중복이 생기지 않고 마감이 바뀌면 기존 일정이 갱신된다.

출력은 `out/alarm.ics`(전체)와 `out/alarm/{slug}.ics`(앨범별).
`vercel.json`이 `.ics`에 `text/calendar`를 붙인다 — 없으면 구독이 아니라 다운로드가 된다.

**12시간제를 쓰지 않는다.** 마감이 `00:59`인데 `AM 12:59`로 나오면 정오로 읽힌다.

**"위드뮤만 비싸다"고 적었던 건 파싱 버그였다.** 목록 카드에 금액이 둘 나온다 —
`16,000원 13,800원 14%`. 앞이 정가(취소선), 뒤가 판매가인데 앞의 것을 읽고 있었다.
고치고 나니 13,800 / 20,500 / 41,000으로 **나머지 4사와 정확히 같다.**
"국내 판매처 가격은 대체로 같다"가 다시 참이다.

**아직 막힌 곳** — 예스24 · 뮤직코리아 · 핫트랙스.

**예스24는 헤드리스로도 값이 안 맞는다.** 정적으로는 쿼리가 아예 반영되지 않고(아래 참고),
헤드리스로 열면 반영되긴 하는데 ① 쿼리 3개 중 2개가 0건으로 돌아올 만큼 불안정하고
② 성공해도 태민 6종 중 **1종만** 렌더된다. 앨범마다 브라우저를 띄워 1종을 얻는 계산이라 접었다.

**예스24는 "열린다"고 잘못 판정했었다.** 검색 URL이 200에 507KB를 돌려주고 앨범명도 들어 있어서
정적으로 되는 줄 알았는데, **쿼리를 바꿔도 결과가 똑같았다** — "태민" · 없는 검색어 · "엔하이픈"이
전부 상품 ID 189개로 동일했다. 앨범명이 보인 건 검색 결과가 아니라 고정 진열대에 그 상품이
있었기 때문이다. **입력을 바꿔도 안 변하는 신호는 신호가 아니다.** 그 뒤로는 몰을 판정할 때
쿼리 두 개를 넣어 응답이 달라지는지부터 본다.

### 헤드리스는 최소한으로 쓴다

`src/browser.mjs`가 공용 브라우저를 하나 띄우고 이미지·폰트·미디어 요청은 막는다.
위드뮤는 **앨범당 검색 1회**만 하고 상세는 안 연다 — 상세에 특전 문구가 없어서(실측 0건) 비용만 든다.
playwright가 없으면 위드뮤만 조용히 빠지고 나머지 4사는 그대로 돈다.

## 초성 검색

팬은 `ㅌㅁ`을 치고 태민을 기대한다. 그런데 `ㅌ`(U+314C)과 `태`(U+D0DC)는 코드포인트가
하나도 안 겹쳐서, 문자열을 그대로 비교하는 검색기는 원리상 못 맞춘다 —
**Fuse.js · MiniSearch · Pagefind 전부 마찬가지다.**

해결은 라이브러리가 아니라 산술이다. 한글 음절은 U+AC00부터
`초성 × 588 + 중성 × 28 + 종성`으로 배열돼 있어서 588로 나누면 초성이 나온다 (`src/hangul.mjs`, 8줄).

**초성 변환은 빌드 때 끝내서 `data-c`에 박는다.** 브라우저는 문자열 비교만 한다 —
자모 분해 코드가 내려가지 않으니 전송량이 안 늘고 의존성도 안 생긴다.

```
태민(TAEMIN) PHASE I : Soft Violence
  data-q  태민taemintaemin태민phaseisoftviolence
  data-c  ㅌㅁtaemintaeminㅌㅁphaseisoftviolence
```

질의가 초성만이면(`ㅌㅁ`) `data-c`를, 아니면 `data-q`를 본다.
카드가 8개 미만이면 검색창을 아예 안 낸다 — 한 화면에 들어오면 방해만 된다.
JS가 없으면 검색창을 숨긴다. 안 되는 입력창을 두는 것보다 낫다.

**한계** — `ㅌ민`처럼 자모와 음절이 섞인 질의는 못 잡는다. 조합 중간 상태(`ㅌㅐㅁ`)도 마찬가지다.
그게 필요해지면 그때가 es-hangul을 넣을 자리다. 조사 붙이기도 거기서 같이 온다.

## 알림 — 캘린더와 푸시를 나눴다

| | 담당 | 인프라 |
|---|---|---|
| **캘린더(.ics)** | 다가오는 **마감** (하루 전·1시간 전) | 없음 (정적 파일) |
| **웹푸시** | **없던 게 생긴 것** (새 예판) | Vercel 함수 + KV |

둘 다 마감을 보내면 같은 일로 알림이 두 번 온다.

**푸시는 페이로드 없이 보낸다.** 내용을 실으려면 `aes128gcm`(ECDH+HKDF)을 직접 구현해야 하는데,
"깨우기"만 보내고 서비스워커가 `/api/latest`를 읽게 하면 암호화가 통째로 필요 없다.
부수 효과가 오히려 낫다 — **알림 문구가 발송 시점이 아니라 열람 시점 기준**으로 맞는다.

남는 건 VAPID JWT 하나뿐이고 WebCrypto로 끝난다 (`src/vapid.mjs`, 의존성 0).

받는 정보는 **푸시 엔드포인트 하나**뿐이다. 이메일도 계정도 좋아하는 아티스트도 안 받는다.
404·410로 응답하는 죽은 구독은 발송하면서 그 자리에서 지운다.

**iOS는 홈 화면에 추가해야 온다.** 사파리 탭에서는 버튼이 눌러도 아무 일도 안 나므로 안내를 대신 낸다.
VAPID 공개키가 없으면 버튼 자체를 안 낸다 — 눌러도 안 되는 버튼을 두는 것보다 낫다.

**이 저장소를 배포하는 Vercel 프로젝트가 둘이다** (`kpop-album`, `kpop-album-benefits`).
크론은 `vercel.json`에 있으니 **양쪽에서 다 돈다** — 둘이 같은 KV를 보면 거의 동시에
같은 "새 앨범"을 읽고 둘 다 발송해서 구독자에게 알림이 두 번 간다.

한쪽의 KV 연결을 끊는 것으로는 못 막는다. 이미 떠 있는 배포에 변수가 구워져 있어서
재배포 전까지 계속 돈다(실측). 그래서 `api/notify.js`가 `VERCEL_PROJECT_PRODUCTION_URL`로
자기를 확인해 **`SITE_URL`이 가리키는 프로젝트에서만 발송한다.**

설정에 필요한 것: Vercel에 Upstash Redis 연결(`KV_REST_API_*` 자동) ·
`VAPID_PUBLIC_KEY`/`VAPID_PRIVATE_KEY`/`VAPID_SUBJECT` 환경변수 ·
GitHub Variables에도 `VAPID_PUBLIC_KEY`(빌드가 버튼을 내려면 필요).

## 알아둘 것

**특전 상태를 넷으로 구분한다.** `—` 하나로 뭉뚱그리지 않는다.

| 상태 | 뜻 |
|---|---|
| 내용 표시 | 파싱 성공 |
| `특전 없음` | 위버스샵 `icons`에 BENEFIT 없음 = 단정 가능 |
| `특전 있음 · 구성 비공개` | Ktown4u가 *"특전 (구성은 비공개입니다)"*로 명시 |
| `증정 종료` / `확인 못함` | 알라딘 종료 문구 / 요청 실패 |

**쿠폰은 총액에서 빼지 않는다.** 알라딘 상품 페이지의 "최대 7,000원 할인쿠폰"은
**"받기"를 눌러야 하고**, `8월 음반 전종 쿠폰 이벤트`라는 **기간 한정 행사**다 (2026-08-27 확인).
그래서 별도 항목으로만 표시한다.

**국내 판매처 상품가는 대체로 같다.** 정가 판매라서다.
차이가 나는 건 ⓐ3만원 미만 소액 구매의 배송비 ⓑ쿠폰 ⓒ**특전 구성**뿐이고, 이 중 ⓒ가 이 도구의 존재 이유다.

## 감시 — 새로 뜬 걸 빨리 안다

전체 빌드는 판매처 5곳을 다 긁어 오래 걸린다. 그래서 하루 두 번뿐이고,
그 주기로는 **예판이 열려도 최대 12시간 뒤에 안다.**

```bash
node watch.mjs          # 뭔가 새로 떴는지만 확인
node watch.mjs --deep   # 위버스샵 158팀 스캔까지 강제
```

비용이 100배 차이 나서 두 층으로 나눴다.

| 층 | 요청 | 주기 | 무엇 |
|---|:-:|:-:|---|
| **A** | **1건** | 15분 | 메이크스타 진행 중 이벤트 목록 |
| **B** | 158건 | 1시간 | 위버스샵 아티스트 전체 예판 스캔 |

**A층이 싼데도 넓다.** 실측에서 이벤트 19건 중 11건이 위버스샵 예판에 없는 앨범이었다
(도경수·앤팀·베이비몬스터 등). 새 컴백은 대개 여기 먼저 뜬다.

B층을 자주 못 도는 건 위버스샵에 **전체 신상품을 한 번에 주는 엔드포인트가 없어서**다.
홈은 아티스트 목록만 주고 `categories/-1/sales`는 400이다. 아티스트별로 158번 요청해야 한다.

변화가 있을 때만 전체 빌드를 부른다. 없으면 3초 만에 끝난다.
변화는 `state/changes.ndjson`에 쌓인다 — **나중에 푸시 알림을 붙이면 보낼 내용이 여기 이미 있다.**

**15분 주기는 저장소가 공개라서 가능하다.** Actions는 실행 시간을 분 단위로 **올림**
청구해서, 감시가 3초로 끝나도 1분으로 셈한다. 비공개였다면 월 2,000분 한도에 걸린다
(15분 주기 = 월 2,880분). 비공개로 되돌린다면 30분으로 낮춰야 한다.

**B층 주기의 한계는 요금이 아니라 위버스샵이다.** 1시간이면 하루 3,800건 —
동시 8개로 20초쯤 몰아치는 게 하루 24번이다. 이보다 당기면 차단 위험이 실질적으로 커진다.

차단이 시작되면 `discoverPreorders`의 `failed`가 올라가고, watch는 그 회차의
**"사라짐" 판정을 스스로 포기한다.** 없는 변화를 만들지 않고, 로그에 경고가 남는다.

## 배포

정적 파일이라 `out/`을 그대로 서빙하면 된다.

- **Vercel** — `vercel.json`에 `outputDirectory: "out"`, 빌드 없음
- **갱신** — `.github/workflows/rebuild.yml`이 하루 두 번(KST 10시·19시) 다시 긁어 `out/`을 커밋한다.
  Vercel이 그 커밋을 보고 자동 재배포한다

빌드를 Vercel에서 돌리지 않는 이유는 **판매처들이 클라우드 IP를 막을 수 있어서**다.
GitHub Actions에서 긁고 결과만 커밋하는 편이 안전하다.

- **특전 이미지를 주는 곳이 위버스샵뿐이다.** 나머지 6곳을 전부 열어 확인했다 —

  판매처별 특전은 판매처가 각자 만드는데 대부분 이미지를 안 만든다
