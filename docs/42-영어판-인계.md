# 영어판 인계 — 프론트 레인으로

> 작성 2026-08-28 · 코드 레인 → 프론트 레인.
> 수요 근거는 [`growth/41-X-초안-20건.md`](growth/41-X-초안-20건.md) §6-B에 있다.

> **현황 (같은 날 늦게) — 프론트가 이미 시작했다. `src/en.mjs`가 있다.**
>
> 아래 §0은 "별도 렌더러를 만들지 마라"고 적었는데 **그쪽이 반대로 갔고, 근거가 더 낫다.**
> `src/en.mjs` 주석에 적힌 이유 두 가지 —
> ① `render.mjs`는 지금 작업이 계속 들어가는 파일이라 로케일 분기를 심으면 충돌한다
> ② 영어판은 국내판과 **정보 축이 갈라질 예정**이다(국제배송 가능 여부·한터 인증)
>
> 내가 §0을 쓸 때는 ②를 몰랐다. 갈라질 거라면 처음부터 나눠 두는 게 맞다.
> **§0은 기록으로 남기고, 실제 방침은 `src/en.mjs` 쪽을 따른다.**
>
> 그쪽이 찾은 검색 실측도 내 것보다 정확하다 —
> 자동완성에 `kpop pob` 10건 · `kpop pob stores` 4건, 반면 `kpop pob comparison`·
> `kpop album pob list`는 0건. **용어를 `benefit`이 아니라 `POB`로 써야 한다.**
>
> 이 문서에서 여전히 유효한 건 **§1 측정치 · §2 함정 셋 · §3 번역 사전**이다.

## 0. 왜 프론트로 넘기나

영어판에 필요한 일의 대부분이 프론트 파일이다.

| 필요한 일 | 파일 | 레인 |
|---|---|---|
| UI 문자열 144개 분리 | `src/render.mjs` | **프론트** |
| hreflang·메타 | `src/seo.mjs` | **프론트** |
| 영어 페이지 렌더 | `src/render.mjs` 파생 | **프론트** |
| `out/en/` 출력·sitemap | `build.mjs` | 코드 |
| 특전 문구 번역 | 데이터 | 코드 |

**별도 렌더러(`render-en.mjs`)를 새로 만들면 안 된다.** 두 벌이 갈라진다 —
2026-08-28 하루에만 `render.mjs`가 369줄 바뀌었다. 영어판은 한국어 렌더의 파생물이라
한 파일 안에서 갈라져야 유지된다.

## 1. 먼저 — 생각보다 작다

실측했다. "번역이 오래 걸린다"는 처음 내 추정이 틀렸다.

| 대상 | 개수 | 글자 |
|---|---:|---:|
| UI 문자열 (`render` 102 · `build` 33 · `seo` 6 · `ics` 3) | 144 | 6,087 |
| 특전 문구 | 63 | 5,695 |
| 구성품 설명 | 75 | 9,309 |
| 랜덤 안내 | 1 | 36 |
| **소계** | **283** | **21,127** |
| ~~한글 상품명~~ | ~~471~~ | ~~28,087~~ |

**상품명 471개(28K자)는 번역이 필요 없다.** 이미 `parseTitle`로 분해해뒀다.

```
원본:  [케타포 Special Gift] [2CD 세트상품] 태민 (TAEMIN) - [PHASE I : Soft Violence] (JEWEL Ver.)
파싱:  edition="JEWEL Ver." · packaging=세트 · events=["케타포 Special Gift"]
```

버전명은 원래 영문이다. 영어판은 원문 대신 파싱된 필드로 그리면 되고,
남는 번역 대상은 `세트/단품/랜덤` 세 단어와 이벤트 표식 몇 개뿐이다.

**그리고 특전 문구는 빌드 간 재사용률 100%였다** (5빌드를 건너뛰어도 동일 문자열).
정적 사전으로 두고 해시로 캐시하면 신규 앨범이 뜰 때 몇 건만 추가된다.
**번역 API를 빌드에 붙일 이유가 없다.**

## 2. 함정 셋 — 이게 실제 위험이다

### 2-A. 배송비·최저가 조합은 국제 사용자에게 **틀린 답**을 준다

번역 문제가 아니라 로직 문제다. 지금 계산은 국내 배송 기준이다.

그런데 국제 팬은 우리 판매처 대부분에서 **직접 못 산다.**
사운드웨이브·예스24 등은 한국 배송지와 가상계좌/계좌이체를 요구하고,
일부는 주민번호·외국인등록번호 인증까지 요구한다. 그래서 GOM(Group Order Manager,
한국의 총대)이나 배대지를 거친다.

→ **영어판에서는 최저가 조합·배송비 섹션을 빼거나 `domestic shipping only` 라벨을 단다.**
   국제 배송비는 우리가 계산할 수 없다. 계산한 척하면 그게 제일 큰 거짓말이 된다.

### 2-B. 조건부 문구 오역은 사용자에게 실제 손해를 입힌다

> 초도제작분 중 일부만 앨범에 삽입되어 증정됩니다

이걸 `included with the first press`로 옮기면 **틀린다.** 초도 전량이 아니라 *일부*다.
이 한 줄 때문에 사면 받는 줄 알고 산다.

→ **아래 §3 사전을 쓰고, 사전에 없는 문구는 번역하지 말고 한국어 원문을 그대로 노출한다.**
   원문 병기가 오히려 낫다 — GOM은 한국 스토어를 직접 다루는 사람들이라 원문을 읽는다.

### 2-C. 판매처 범위를 반드시 밝힌다

영어권 `pob list`에는 중국계·글로벌 판매처(jingdong, starriver, mini record,
iminitv, kmstation, withfans)가 절반을 차지한다. **우리는 국내 7곳만 본다.**

→ 영어판 모든 페이지에 `Korean domestic stores only` 를 명시한다.
   "전체 POB 정리"로 보이면 절반이 빠진 표가 되고 그 바닥은 바로 알아본다.

## 3. 특전 문구 — `src/i18n-benefit.mjs` (만들어 뒀다)

**번역이 아니라 구조 추출이다.** 규칙 기반 번역을 먼저 만들었다가 폐기했는데,
폐기한 이유가 그대로 §2-B의 실증이다.

```
원문   미공개 셀피 포토카드 3종 (5종 중 랜덤)
번역   unreleased selca photocard 3 types (1 of 5, random)   ← 5종 중 3종인데 1종처럼 읽힌다
```

문법은 멀쩡하고 뜻만 틀렸다. **원문을 그대로 두는 것보다 나쁘다** — 읽는 사람이 틀린 줄 모른다.

그래서 문장을 옮기지 않고 품목과 개수만 뽑는다.

```js
import { benefitLine } from './i18n-benefit.mjs';

benefitLine('케타포 특전 : 미공개 포토카드 2종 중 1종 랜덤')
// → 'unreleased photocard, 1 of 2, random'

benefitLine('초도제작분 중 일부만 앨범에 삽입되어 증정됩니다')
// → 'only in part of the first press — not every copy'

benefitLine('...알 수 없는 새 문구...')
// → null   ← 이때 **한국어 원문을 그대로 보여줘라.** 빈칸으로 두지 마라.
```

저장된 특전 문구 48건 전부 요약되고, 정확도 회귀 케이스 7건을 테스트했다.
사전이 낡으면 `benefitStats()`로 알아챌 수 있다.

아래는 그 사전이 아는 어휘다.

| 한국어 | English |
|---|---|
| 미공개 포토카드 | unreleased photocard |
| 미공개 셀피/셀카 포토카드 | unreleased selca photocard |
| N종 중 M종 랜덤 | M of N, random |
| N종 1세트 | set of N |
| 각 앨범당 | per album |
| 예약 판매 구매자 한정 | pre-order only |
| Weverse Global 단독 특전 | Weverse Global exclusive |
| 케타포 특전 | Ktown4u exclusive |
| 알라딘 특전 | Aladin exclusive |
| 수량 소진시까지 | while supplies last |
| 증정 종료 | ended |
| **초도제작분 중 일부만 앨범에 삽입** | **only inserted in part of the first press — not every copy** |
| 럭키드로우 참여 기회 N회 | N lucky draw entries |
| 리무버블 스티커 | removable sticker |
| 오피셜 단체컷 | official group photo |

## 4. 프롬프트

```
poc/ 에 영어판을 추가한다. src/render.mjs를 고쳐서 한 파일에서 두 언어를 낸다.
별도 렌더러 파일을 새로 만들지 마라 — 두 벌이 갈라진다.

할 일:
1. render.mjs의 한글 UI 문자열 102개를 사전으로 분리하라.
   const L = { ko: {...}, en: {...} } 형태로 두고 렌더 함수가 locale을 받게 한다.
   **한국어 출력은 지금과 바이트 단위로 같아야 한다** — 기존 페이지가 바뀌면 안 된다.
2. seo.mjs에 hreflang을 넣어라 (ko ↔ en 양방향, x-default는 ko).
3. 영어판에서는 배송비·최저가 조합 섹션을 빼거나 "domestic shipping only" 라벨을 달아라.
   국제 배송비는 계산할 수 없다. 계산한 척하면 안 된다.
4. 모든 영어 페이지에 "Korean domestic stores only"를 명시하라.
5. 특전 문구는 src/i18n-benefit.mjs의 사전을 쓰고, 사전에 없으면 번역하지 말고
   한국어 원문을 그대로 보여줘라. 기계번역해서 사실처럼 내보내지 마라.
6. 상품명(title)은 번역하지 마라. parseTitle이 만든 edition/packaging/events로 그려라.

절대 하지 말 것:
- build.mjs를 건드리지 마라. out/en/ 출력 배선은 코드 레인이 한다.
  렌더 함수 시그니처만 정해서 docs/42-영어판-인계.md에 적어두면 붙인다.
- src/ 수집기를 건드리지 마라.
- 조건부 문구를 기계번역하지 마라 (§2-B 참고).

검증: 영어판을 켠 뒤에도 out/album/*.html의 한국어 출력이 이전과 동일해야 한다.
diff로 확인할 것.
```

## 5. 코드 레인이 대기 중인 것

렌더 함수 시그니처가 정해지면 이걸 붙인다. **먼저 하지 않는다** — 시그니처를 모르면
헛돈다.

- `build.mjs` — `out/en/album/<slug>.html` · `out/en/index.html` 출력
- `sitemap.xml` — en 경로 추가
- `out/en/` 정리 로직 (예판 종료 앨범)

시그니처가 정해지면 이 문서에 한 줄 적어주면 된다.

## 6. 순서 제안

**영어 초안 5건([`growth/41`](growth/41-X-초안-20건.md) §6-B)을 먼저 올려보고,
반응이 오면 영어판을 만드는 게 낫다.**

지금 만들면 `pob list` 포맷이 실제로 먹히는지 모르는 상태에서 번역·hreflang·출력 경로를
다 붙이게 된다. 초안은 이미 나와 있어서 검증 비용이 0이다.

다만 이 문서를 먼저 쓴 이유는, 반응이 왔을 때 **측정치와 함정이 이미 정리돼 있어야
바로 시작할 수 있어서**다.
