# `vercel.json` 헤더 — 왜 이렇게 뒀나

`vercel.json`은 JSON이라 주석을 못 단다. 처음엔 각 헤더 항목에 `"//"` 키로 설명을 넣었는데
**Vercel이 배포를 거부했다** — `headers[]` 항목은 `source`·`headers`·`has`·`missing`만
허용하고 나머지 키는 스키마에서 막힌다.

증상이 헷갈린다. 빌드 로그가 아니라 **커밋 상태에 "Deployment failed"만 뜨고**
`target_url`이 프로젝트 설정 문서를 가리킨다. 빌드가 아니라 **설정 파싱**에서 죽은 것이다.
(커밋 `861820e`에서 두 프로젝트가 동시에 실패했고 그 앞 `eafa35c`는 성공이었다.)

**그래서 근거는 여기 적는다. `vercel.json`에 주석 키를 다시 넣지 마라.**

---

## 보안 헤더 — `/(.*)`

`script-src`에 `'unsafe-inline'`이 남아 있다. 이 사이트는 카운트다운·초성검색·버전탭·
특전 제보를 **전부 인라인 `<script>`** 로 넣는다(의존성 0을 지키는 방식이다).
nonce를 쓰려면 요청마다 값이 달라져야 하는데 우리는 정적 파일이라 그럴 수가 없다.

그래도 나머지는 실제로 막힌다 — `base-uri`·`form-action`·`frame-ancestors`·`object-src`.

`img-src`를 호스트로 못 적는 이유는 **판매처 CDN이 계속 늘기 때문**이다
(ktown4u · aladin · weverseshop · makestar · musicplant · 팬 제보 이미지…).
한 곳이라도 빠지면 그 판매처 사진만 조용히 사라진다 — 특전 사진이 이 사이트의 존재 이유라
그 실패는 치명적이다. `https:`로 열어두되 `http:`는 막는다.

## 캐시 — 세 갈래

| 대상 | 값 | 이유 |
|---|---|---|
| `/api/(.*)` | `no-store` | `/api/latest`는 서비스워커가 **푸시 알림을 받은 직후** 읽는다. 캐시되면 "방금 뜬 예판"이 옛날 것으로 나온다 |
| `/`, `/album/(.*)` | `max-age=0, s-maxage=3600, stale-while-revalidate=86400` | 브라우저는 매번 확인하고 CDN이 1시간 쥔다. 재빌드가 하루 두 번이고 **새 배포가 Vercel 캐시를 무효화**하므로 낡은 걸 보여줄 위험이 없다 |
| `/og/(.*)` | `max-age=86400, s-maxage=604800, immutable` | 공유 카드는 파일명이 내용에 묶여 있어 오래 쥐어도 안전하다 |
| `/(.*).ics` | `text/calendar` + 1시간 | **Content-Type이 없으면 구독이 아니라 다운로드가 된다** |

## 배포가 실패하면 먼저 볼 것

```bash
gh api repos/parkhb1181/kpop-album-benefits/commits/<sha>/status \
  --jq '.state, (.statuses[] | "\(.context) | \(.state) | \(.description)")'
```

`target_url`이 문서 페이지면 **`vercel.json` 문제**다. 빌드 로그를 뒤질 필요가 없다.
